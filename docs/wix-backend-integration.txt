1. THE FLOW IN ONE PAGE
------------------------------------------------------------------

  Step  Who      What
  ----  -------  ----------------------------------------------------------
  1     Next     User clicks "Continue to Wix". Next sets a signed state
                 cookie and redirects to Wix's app installer.
  2     Wix      User picks a site and installs the Rankoya app. Wix
                 redirects to Next's callback with ?state=...&signedInstance=...
  3     Next     Checks the state cookie, verifies signedInstance with the
                 app secret, reads instanceId / metaSiteId / siteOwnerId.
  4     Next     Gets a Wix access token for that instance and checks Wix
                 Blog is on the site.
  5     Next     POST /api/sites/{site}/publishing/connections   -> LARAVEL SAVES
  6     Next     POST /api/sites/{site}/publishing/connections/{id}/test
                                                                 -> LARAVEL TESTS
  7     Laravel  On publish: token -> HTML to rich content -> create and
                 publish a Wix Blog post -> save post id and live URL.
                                                                 -> LARAVEL PUBLISHES

Steps 1 to 4 stay in Next. Steps 5 to 7 are the backend work (sections 3 to 5).
Step 7 currently only exists in Next as a test tool (section 6).

2.2 Callback: verify signedInstance
    Files: src/app/api/integrations/wix/callback/route.ts
           src/lib/integrations/connectors/wix.ts

    Wix calls: GET /api/integrations/wix/callback?state=<nonce>&signedInstance=<sig>.<data>

    signedInstance is "<signature>.<data>". It is signed, not encrypted:
      data      = base64url of a JSON object
      signature = base64url( HMAC-SHA256( data, WIX_APP_SECRET ) )

      export function verifySignedInstance(signed: string): WixInstance {
        const [sig, data] = signed.split(".");
        const expected = createHmac("sha256", appSecret).update(data).digest("base64url");
        const a = Buffer.from(sig.replace(/=+$/, ""));   // some installs pad with "="
        const b = Buffer.from(expected);
        if (a.length !== b.length || !timingSafeEqual(a, b)) throw new IntegrationError("signature", 400);
        return JSON.parse(Buffer.from(data, "base64url").toString());
      }

3. BACKEND: SAVE THE CONNECTION
------------------------------------------------------------------

  POST /api/sites/{site}/publishing/connections
  Authorization: Bearer <user's Sanctum token>
  Content-Type: application/json

  {
    "name": "Wix",
    "platform": "wix",
    "method": "api",
    "credentials": {
      "instance_id": "143684d1-02b1-47b7-b7a2-c6a278b52a4c",
      "site_id": "db8d97c6-3e98-43b2-8d76-7225ce45885a"
    },
    "config": {
      "auth": "app",
      "author_member_id": "3ee49955-4263-4ad5-84bb-42a2f3710c8b"
    }
  }

  Validation when platform = wix and config.auth = app:

    credentials.instance_id    required, string, max 255
    credentials.site_id        optional, string (informational)
    config.auth                in:app
    config.author_member_id    optional, string, max 255 (the post author)
    credentials.access_token   NOT required
    config.collection_id       NOT required

  No token is stored. Tokens last about 4 hours, so make one per publish.

  Expected response: 201, { success: true, data: { id, ... } }, status "pending".
  Also needed: register WixPublishingProvider in PublishingProviderManager,
  otherwise every Wix connection gets "This publishing integration is not
  available yet." (422).


4. BACKEND: TOKEN AND CONNECTION TEST
------------------------------------------------------------------

4.1 Token (WixOAuthService::createAccessToken($instanceId) already does this)

  POST https://www.wixapis.com/oauth2/token
  Content-Type: application/json

  {
    "grant_type": "client_credentials",
    "client_id": "<WIX_CLIENT_ID>",
    "client_secret": "<WIX_CLIENT_SECRET>",
    "instance_id": "<credentials.instance_id>"
  }

  -> 200 { "access_token": "..." }

  Send it on every Wix call as:   Authorization: <access_token>
  There is NO "Bearer" prefix.

  Next reference:

      export async function wixToken(instanceId: string): Promise<string> {
        const res = await fetch("https://www.wixapis.com/oauth2/token", {
          method: "POST",
          headers: { "Content-Type": "application/json", Accept: "application/json" },
          body: JSON.stringify({
            grant_type: "client_credentials",
            client_id: config.appId,
            client_secret: config.appSecret,
            instance_id: instanceId,
          }),
        });
        const body = await res.json();
        if (!res.ok || !body?.access_token) throw new IntegrationError("token", 502);
        return body.access_token;
      }

4.2 POST /api/sites/{site}/publishing/connections/{id}/test

  No change to the request or response. For Wix with config.auth = app:

    1. Make a token (4.1).
    2. GET https://www.wixapis.com/blog/v3/categories?paging.limit=1
       Authorization: <access_token>
    3. 2xx        -> status "active".
       403 / 404  -> Wix Blog isn't on the site -> status "error".
       Token call fails -> the app was removed or the instance id is wrong.

5.3 Create and publish the post in one call

  POST https://www.wixapis.com/blog/v3/draft-posts
  Authorization: <access_token>
  Content-Type: application/json

  {
    "draftPost": {
      "title": "<article title, max 200 chars>",
      "richContent": { "nodes": [ ... ] },
      "excerpt": "<meta description, max 500 chars>",
      "memberId": "<config.author_member_id>"
    },
    "publish": true
  }

  -> 200 { "draftPost": { "id": "<wix post id>", ... } }

  Save draftPost.id as external_id.
  On failure Wix returns { "message": "...", "details": { ... } }; store the
  status and message on the publication.

  Next reference:

      const res = await fetch(`${WIX_API}/blog/v3/draft-posts`, {
